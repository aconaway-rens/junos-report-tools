    Where the numbers come from. Everything on this page is read out of the text above — the file
    you open is read in the browser and never leaves it. Routes marked config are the
    static routes in the configuration plus the connected routes implied by each interface
    address; their egress interface is worked out by matching the next-hop against the configured
    connected subnets, exactly as the device would for a directly attached next hop. That is
    intent, not the live RIB — routes learned by OSPF, BGP, or any other protocol appear only
    if show route output is pasted alongside the config, and those rows are marked
    show route. A next-hop that falls outside every configured subnet is reported
    unresolved rather than guessed at. Pre-shared keys are never rendered.
    


    Configuration and live state answer different questions. The optional panes take
    show route, show security ipsec security-associations detail and
    show security ike security-associations detail. Where a capture overlaps the
    configuration the live one wins, and the difference is reported: a static route that never
    made it into the RIB, a phase 1 that came up on algorithms the proposals merely allowed, a
    tunnel negotiated at phase 1 with no phase 2 SA behind it. Take the captures from the same
    box at the same time — a stale one attributes traffic to the wrong place.
